# Wazuh_Automation_with_Suricata
In this project, I made a Wazuh home lab in which I made an interesting scenario and used suricata to automate the process. Furthermore, i also used a python script which automatically blocks a suspicious ip based on alert generated by Wazuh-dashboard.



# 🛡️ Suricata + Wazuh Automated Threat Detection & Response

> **A hands-on cybersecurity lab integrating network intrusion detection, SIEM monitoring, and automated response using Suricata, Wazuh, Python, Docker, and Ubuntu WSL2.**

---

## 📌 Project Overview

This project demonstrates a practical **Security Operations Center (SOC)-style detection and response pipeline**.

The goal was to integrate **Suricata IDS with Wazuh** so that network security events detected by Suricata can be collected, analyzed, visualized, and used as the basis for automated response.

A Python-based response engine was also developed to monitor Suricata's EVE JSON log and respond to detected alerts by maintaining a local IP blocklist.

# 🔍 Suricata IDS

Suricata is responsible for monitoring network traffic and generating security events.

Its EVE JSON output is stored at:

```text
/var/log/suricata/eve.json
```

The EVE JSON format provides structured information such as:

* Timestamp
* Event type
* Source IP
* Destination IP
* Source port
* Destination port
* Protocol
* Alert signature
* Alert severity

Example event structure:

```json
{
  "event_type": "alert",
  "src_ip": "192.168.x.x",
  "dest_ip": "192.168.x.x",
  "alert": {
    "signature": "Example Alert",
    "severity": 1
  }
}
```

# 🖥️ Wazuh Integration

Wazuh is used as the centralized security monitoring component of the project.

Suricata events are made available to the Wazuh Manager so that security events can be:

1. Collected
2. Parsed
3. Evaluated
4. Assigned an alert level
5. Displayed in the Wazuh Dashboard
6. Used for response automation

This creates a connection between **network-level detection** and **centralized security monitoring**.

---

# 🤖 Automated Response

A Python response engine was developed to monitor:

```text
/var/log/suricata/eve.json
```

The script continuously monitors newly generated Suricata events and looks for:

```text
event_type = alert
```

When an alert is detected, the script extracts information including:

* Source IP
* Destination IP
* Alert signature
* Alert severity
* Timestamp

The response component maintains a local blocklist:

```text
~/blocked_ips.json
```

This allows the project to demonstrate the concept of:

```text
Detection → Analysis → Response
```

---

# 🚨 High-Severity Response

An important part of the project is distinguishing between ordinary events and potentially serious security alerts.

The intended response workflow is:

```text
Suricata Alert
      │
      ▼
Determine Severity
      │
      ├── Low/Informational
      │       │
      │       ▼
      │    Monitor
      │
      └── High Severity
              │
              ▼
        Automated Response
              │
              ▼
        Source IP Handling
```

This approach helps reduce unnecessary automated actions while focusing response mechanisms on higher-priority events.
